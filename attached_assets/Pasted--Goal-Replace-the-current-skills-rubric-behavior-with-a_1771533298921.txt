3) Operational definitions to implement (key changes)
3.1 Spacing rule update (Items 8 and 10)

Replace “~1 mm” with “consistent / no gaping.”

Score YES if:

Stitching is reasonably consistent AND

Vessel edges are approximated without visible gaps/dog-ears AND

No obvious leak-risk gaps or edge mismatch.

Score NO only if:

Spacing is clearly irregular AND causes visible gaping/malapposition OR

Large gaps/edge mismatch that would plausibly leak/stenose.

Hard prohibition:

The model must not claim numeric millimeter spacing unless it cites a measurement proxy visible in-frame (e.g., known needle width) and even then it must downgrade confidence. Easiest: forbid numeric mm estimates entirely.

3.2 Technique equivalence (Items 5, 7, 9)

Implement as outcome/intent rather than literal method enforcement.

Item 5 (heel establishment):

YES if heel is correctly established and remains aligned, regardless of single vs double-armed start.

NO only if heel alignment is wrong/unstable and not corrected.

Item 7 (right-angle pass / transfer):

YES if safe progression to the opposite side occurs OR if the method makes the “pass” irrelevant (single-armed continuous) and there is no twist/malalignment and the back wall is completed appropriately.

NO only if failure to transfer/progress causes twist/malalignment/inability to complete correctly, or if transfer attempt is unsafe and consequential.

Item 9 (toe trimming):

YES if toe/apex fit is appropriate, whether trimming is observed or not.

NO only if toe/apex fit is clearly inappropriate (redundancy/shortage) and not corrected.

4) Deterministic proficiency rule (Item 13)

Make Item 13 computed in code, not judged by the model.

Recommended apples-to-apples rule for your dataset:

Proficiency = YES if:

Items 2, 8, 10, 11 are YES (core technical safety/outcome gates), AND

All other items 1–11 are YES OR ASSUMED YES (under your policy), AND

Economy (item 12) does not gate proficiency.

Proficiency = NO if:

Any of the core gates (2, 8, 10, 11) are NO, OR

Two or more other observed items are NO (optional stricter threshold; keep configurable).

Make the gating list and threshold config-driven:

coreGates = [2,8,10,11]
maxNonCoreObservedNo = 1
5) Economy scoring: make it auditable and less drift-prone

Add two constraints to the prompt and enforce in validation:

Require “wasted motion event” list (0–5 events).

Constrain score from event count + flow organization.

Mapping (implement in code as a check; if violated, request a re-score):

If 0–1 wasted-motion events AND flow_organization = organized → score must be 4–5

If 2–3 events OR flow_organization = mixed → score must be 3

If 4–5 events OR flow_organization = disorganized → score must be 1–2

Also add explicit instruction:

“Do not penalize slow pace unless it causes wasted motion or repeated resets.”

This directly targets your observed mismatch where AI sometimes equates “slow/careful” with low economy.

6) Prompt contract (what the model must do)

You will likely have a “video summary / feature extractor” stage (model describes what it saw) and a “rubric scorer” stage.

6.1 Rubric scorer system prompt (core)

Key clauses to include (these are the discipline enforcers):

“You are scoring a retrospective checklist. Only score items 1–14. Do not introduce new categories.”

“Spacing is judged by consistency and approximation, not millimeters. Do not estimate mm.”

“Technique steps allow equivalent methods if the intent/outcome is satisfied.”

“Non-observable items default to YES and must be tagged as ASSUMED in observability with explanation.”

“Return ONLY valid JSON matching the schema. No extra text.”

“Item 13 will be derived by code; output a placeholder or omit it if desired.”

6.2 Model output validation

Server-side validation steps:

Schema validation

Check allowed values

Check economy constraints (event count vs score)

If invalid: automatically re-prompt with “Your output violated constraints X; re-issue valid JSON only.”
